TL;DR

知识库的 GitHub 登录有两条通道。部署在 GitHub Pages 上的页面用 OAuth 授权，这是主通道，四步走完：创建 OAuth App → 填写设置 → 授权 → 自动识别身份。本地双击打开（file:// 协议）时 OAuth 不可用，改用 个人访问令牌（PAT）直连。能否解锁编辑与同步，取决于设置里填写的「你的 GitHub 用户名」和实际登录账号是否一致，比对时大小写不敏感。

你将学到什么

  • □ 创建一个 GitHub OAuth App，并填对 Authorization callback URL
  • □ 在知识库设置窗完成各项配置并发起授权
  • □ 分清登录后「已登录」与「已识别为作者」的区别
  • □ 在本地 file:// 场景用 PAT 完成连接
  • □ 排查常见登录失败

项要求

一、两种登录方式怎么选

维度方式 A：OAuth 授权方式 B：个人访问令牌（PAT）
适用场景部署在 GitHub Pages 的知识库本地 file:// 双击打开的知识库
前提条件一个 OAuth App 的 Client ID一个勾选 repo 权限的 PAT
令牌管理授权后自动获取并存本地，无需手动创建手动创建、手动粘贴，过期要自己换
权限粒度授权页固定申请 repo 范围创建时自选，建议同样只给 repo
定位线上部署首选本地体验与 OAuth 不可用时的备选

两条通道的最终效果相同：登录态都保存在浏览器本地，作者功能的解锁规则一致。

二、方式 A：OAuth 授权登录（四步）

OAuth 授权把身份确认交给 GitHub，令牌换取在页面本地完成，不经过任何第三方服务器。整条流程分四步。

Step 1：创建 OAuth App

  1. 登录 GitHub，打开 https://github.com/settings/developers（Settings → Developer settings → OAuth Apps）。
  2. 点 New OAuth App，按下表填写：
字段填什么示例
Application name随意，仅用于授权页展示沉潜知识库
Homepage URL知识库的访问地址https://你的用户名.github.io/仓库名/
Authorization callback URL与 Homepage URL 完全一致https://你的用户名.github.io/仓库名/
  1. 点 Register application 完成创建。

  注意：Authorization callback URL 必须与页面实际访问地址逐字符一致，包括结尾的斜杠。这是整条流程里最常见的失败点。地址栏里是 https://user.github.io/repo/（带斜杠），设置里写成不带斜杠的 https://user.github.io/repo，授权后 GitHub 会直接报 redirect_uri mismatch。最稳的做法是从地址栏复制 URL 原样粘贴。

创建完成后，页面上的 Client ID 就是下一步要用的值，形如 Iv1. 开头的一串字符。Client Secret 本流程不使用，无需理会。

Step 2：在知识库里填写 GitHub 设置

  1. 打开知识库页面，点右上角 GitHub 登录。没有配置过时会自动弹出设置窗，之后也可以从右上角用户菜单再次进入。
  2. 按下表逐项填写：
设置项何时必填说明默认值
OAuth Client ID方式 A 必填粘贴 Step 1 拿到的 Client ID（Iv1. 开头）空
你的 GitHub 用户名（作者标识）两种方式都必填你自己的登录名，决定谁能解锁作者功能空
仓库所有者同步时需要一般是你的用户名空
仓库名同步时需要存放知识库的仓库空
分支同步时需要推送目标分支main
仓库内存储目录同步时需要文章在仓库里的顶层目录knowledge-base
个人访问令牌方式 B 必填填 PAT，见本文第三部分空
  1. 点 保存，弹出「已保存」即表示配置已写入浏览器本地。

  注意：「你的 GitHub 用户名」填的是登录名，也就是 github.com/ 后面那一段，不是个人主页上显示的昵称。

Step 3：发起授权

设置保存后，再点一次右上角 GitHub 登录，浏览器会跳转到 GitHub 授权页。这一跳背后按顺序发生四件事：

  1. 页面本地生成一对 PKCE 密钥：一个随机 verifier 和它的 SHA-256 摘要 challenge，同时生成一个随机 state，三者暂存在当前标签页的 sessionStorage 里。
  2. 带着 client_id、redirect_uri、scope=repo、state、code_challenge 跳转到 GitHub 授权地址。
  3. 在 GitHub 授权页确认权限范围，点 Authorize。
  4. GitHub 回调到知识库地址，URL 上带回 code；页面先比对 state 一致，再用 code 加 code_verifier 换取访问令牌，最后请求 /user 接口确认身份。

整个过程不需要 Client Secret，令牌也不会经过任何第三方服务器。

验证：授权页应显示你在 Step 1 填写的 Application name，权限提示包含对仓库的读写。

Step 4：识别身份

回调处理完成后页面刷新，右上角出现你的头像和登录名，同时弹出两种结果之一：

  • 已识别为作者：登录名与设置的作者标识一致，编辑文章、上传、同步功能全部解锁。
  • 已登录：登录成功，但登录名不是配置的作者，只能浏览，作者功能保持隐藏。

三、方式 B：个人访问令牌（PAT）连接

本地双击打开的知识库页面走不了 OAuth，改用个人访问令牌直连：先创建令牌，再粘贴连接。

为什么本地双击打开时要用 PAT

两个限制叠在一起：

  1. file:// 协议下页面地址形如 file:///C:/...，GitHub 不接受这类地址作为回调，OAuth 跳转无法完成。
  2. PKCE 依赖 Web Crypto API，该 API 只在安全上下文（https:// 或 localhost）中可用，file:// 不在其列。

因此在本地双击打开的页面里，点登录按钮时设置窗也会提示改用「个人令牌」连接。

创建 PAT

  1. 打开 GitHub Settings → Developer settings → Personal access tokens。
  2. 选 Tokens (classic)，点 Generate new token (classic)。
  3. 权限只勾选 repo，这是读写仓库内容所需的最小范围；过期时间按需设置。
  4. 点生成后复制令牌，形如 ghp_ 开头的一串字符。这个值只完整显示一次，离开页面后无法再查看，丢了只能重新生成。

令牌连接

  1. 打开知识库设置窗，先填好「你的 GitHub 用户名」「仓库所有者」「仓库名」等项。
  2. 在「个人访问令牌」一栏粘贴令牌，点 个人令牌连接（该按钮会顺手保存窗内其余配置）。
  3. 连接结果与方式 A 相同，同样会弹「已识别为作者」或「已登录」。

  注意：fine-grained token 也能用，但需要额外对目标仓库勾选 Contents 的读写权限，否则上传会失败。第一次用建议直接用 classic token。

四、登录后能做什么

以作者身份登录后，知识库多出三样能力：

功能入口作用
编辑文章文章页右上角「编辑文章」修改标题与 HTML 正文，内置文章的修改保存在浏览器本地
上传文件夹或文章面板上的「☁ 上传」把单篇文章或整个文件夹推到仓库
同步到 GitHub工具栏「同步到 GitHub」一次同步全部文章

仓库内的路径与知识库目录结构一一对应：文件名取文章标题，非法字符（\ / : * ? " < > |）替换为 _，内容是带基础样式的独立 HTML，可以直接在浏览器打开。

五、常见问题排查

现象原因处理
授权后 GitHub 报 redirect_uri mismatchcallback URL 与页面地址不一致，常见是少结尾斜杠从地址栏复制 URL，原样粘贴进 OAuth App 设置
弹窗提示「state 校验不通过」sessionStorage 被清理，或在新标签页里发起授权重新点一次登录，过程中不要清浏览器数据
登录成功但没有「编辑文章」「上传」按钮登录名与设置的作者标识不一致进设置检查「你的 GitHub 用户名」，确认填的是登录名
弹窗提示「连接失败：令牌无效或已过期」PAT 过期、被撤销，或权限范围不足重新生成勾选 repo 的令牌再连接
本地双击打开，点登录无反应或提示不可用file:// 下 OAuth 与 Web Crypto 都受限改用 PAT 连接（方式 B）
换设备或清缓存后要重新登录登录态按「浏览器 + 访问地址」隔离存本地属预期行为，重要内容先同步到仓库

六、安全与隐私提示

  • PAT 等同于密码级凭证：只授予必要的 repo 范围，过期时间按需设置，不要在公开场合粘贴。
  • Client ID 不是秘密，可以随页面公开；本流程不使用 Client Secret。
  • 令牌与登录态保存在浏览器 localStorage，按「浏览器 + 访问地址」隔离。公共电脑上用完，记得从右上角头像菜单点「退出登录」。
  • 清除浏览器数据会同时清掉本地登录态和尚未同步的本地修改，重要内容建议及时「同步到 GitHub」做备份。
